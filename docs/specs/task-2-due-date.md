# Task 2 規格：待辦期限

> 練習專案，用來試跑半自動協作流程。使用者已核可本計畫（2026-10-02）。

## 產品目標

使用者新增待辦時可以順便設定期限，避免忘記有時效的事情。

## 行為與驗收標準

1. 新增區多一個日期欄位（選填）。不填期限也能照常新增。
2. 有期限的待辦，在文字下方顯示期限，格式為「期限：10/15（三）」。
3. 過期的待辦要提醒使用者（使用者 2026-10-02 決定）：
   - 以使用者裝置的當地日期判斷；**期限早於今天**才算過期，今天到期不算。
   - 過期且**未完成**的待辦，在期限旁顯示文字標籤「已逾期」（不可只靠顏色）。
   - 勾選完成後不再顯示「已逾期」；取消勾選且仍過期時再次顯示。
4. 既有的新增、空白檢查、勾選、空狀態、鍵盤操作與淡入動效維持 Task 1 的行為。

## 技術約束

- 沿用 Task 1：`todo.js` 純函式、`node:test`、不安裝套件。
- `addTodo(list, text, dueDate)` 新增選填的第三個參數（`YYYY-MM-DD` 字串或省略）；省略時待辦沒有期限。
- 與「今天」有關的判斷，日期要能從外部傳入，測試不可依賴執行當天的日期。

## 視覺方向

沿用 Task 1。

## 不在範圍內

儲存、刪除、編輯、修改既有待辦的期限、排序。
